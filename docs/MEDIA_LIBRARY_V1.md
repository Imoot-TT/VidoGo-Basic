# VidoGo Basic 素材库 V1 目标方向

> 文档状态：第一版功能基线
> 记录日期：2026-09-08
> 适用项目：`VidoGo-Basic/`
> 目标版本：待排期

## 1. 文档目的

本文档定义 VidoGo Basic 素材库第一版的产品目标、功能边界、数据关系、页面结构和验收标准。

第一版重点解决以下问题：

- 同一个来源视频下载视频、提取 MP3、下载封面或字幕时，被拆成多个互不关联的目录或条目。
- 同一张封面被不同下载动作重复保存，浪费磁盘空间。
- 下载完成后只能在下载队列和文件夹中寻找结果，缺少长期、稳定的素材管理入口。
- 用户无法直观看出一个来源项目已经包含哪些视频、音频、图片和字幕。
- 本地文件被移动或删除后，软件内缺少明确状态和修复入口。

## 2. 产品定位

素材库是“下载结果的长期管理中心”，下载队列是“当前和历史任务的过程管理中心”。两者职责必须分开。

```text
浏览器发现媒体
  → 创建下载任务
  → 下载队列显示进度
  → 文件完成并写入项目目录
  → 更新 metadata.json 与素材索引
  → 素材库展示最终结果
```

第一版以“媒体项目”为主要管理对象，而不是以单个文件为主要管理对象。

一个媒体项目对应一个稳定的来源，例如一个 YouTube 视频、一个 TikTok 视频或一个网页媒体条目。该项目可以包含多种素材。

```text
媒体项目
├─ 视频：一个或多个清晰度、编码或格式版本
├─ 音频：MP3、M4A 等音频版本
├─ 图片：一张共用封面，以及未来可能出现的其他图片
├─ 字幕：不同语言、自动字幕或人工字幕
└─ metadata.json：项目和素材清单
```

## 3. 第一版核心原则

### 3.1 一个来源只生成一个媒体项目

- 优先使用 `sourceGroupId` 识别同一个来源。
- 当 `sourceGroupId` 不可用时，使用 `provider + mediaId` 识别。
- 再无法识别时，才回退到规范化来源 URL 或项目目录。
- 项目标题变化或项目文件夹被重命名时，不应产生新的项目身份。

### 3.2 一个项目只保存一份共用封面

- 项目封面是图片素材，角色为 `cover`。
- 视频、音频和字幕条目只引用项目封面，不各自复制封面文件。
- 再次点击“下载封面”时，如果同一封面已经存在，不重复创建文件和素材记录。
- 如果获得质量更高或格式更合适的封面，应执行明确的替换或保留策略，而不是静默生成重复文件。

### 3.3 项目关系高于文件类型

- 素材库默认展示项目，而不是把全部视频、MP3、封面和字幕平铺在首页。
- “全部素材”作为二级视图保留，用于跨项目查找某一种文件。
- 从任意单个素材都能返回其所属媒体项目。

### 3.4 磁盘文件是真实资产，索引用于快速管理

- 项目目录内的 `metadata.json` 是可随目录移动的项目清单。
- 应用数据目录内的 `media-library.json` 是全局查询索引和状态缓存。
- 索引丢失时，可以通过扫描项目目录和 `metadata.json` 重建。
- 不应要求用户只能通过软件移动项目目录；外部变更必须能够被重新扫描并反映状态。

## 4. 第一版功能范围

### 4.1 素材库入口

- 在 VidoGo Basic 现有主侧栏中增加“素材库”入口。
- 建议位置：下载之后、历史之前。
- 使用现有应用标题栏、主侧栏、主题和多语言体系。
- 不引入原型中的第二套品牌栏或固定 250px 全局侧栏。

### 4.2 项目视图

素材库默认打开“项目”视图，每个媒体项目显示一张卡片或一行记录。

项目卡片至少显示：

- 共用封面；
- 项目标题；
- 来源平台；
- 来源媒体 ID（可在详情中显示）；
- 最近更新时间；
- 视频、音频、图片、字幕数量；
- 项目占用总空间；
- 项目状态：正常、部分文件缺失、全部文件缺失。

项目视图支持：

- 网格和列表切换；
- 按最近更新、标题、总大小排序；
- 按平台、素材类型、状态筛选；平台选项直接读取主页“平台管理”中启用的平台，不根据已有素材反推；
- 搜索标题、平台、媒体 ID 和来源 URL；
- 手动刷新素材库；
- 打开项目详情；
- 打开项目文件夹；
- 将整个项目移入系统回收站。

### 4.3 项目详情

点击项目后，在当前页面右侧打开详情面板；必要时也可以扩展为独立详情页。第一版优先采用详情面板，减少页面跳转。

详情顶部显示：

- 项目封面和标题；
- 来源平台；
- 来源页面链接；
- 媒体 ID；
- 项目目录；
- 创建时间和最近更新时间；
- 素材数量和总大小。

来源页面统一在 VidoGo 内嵌浏览器的新标签页打开，不跳转到外部浏览器。

详情内容按以下顺序分组：

1. 视频
2. 音频
3. 图片
4. 字幕

每个素材条目至少显示：

- 文件名；
- 素材类型和角色；
- 文件格式；
- 文件大小；
- 视频清晰度和编码（适用时）；
- 字幕语言、自动/人工状态（适用时）；
- 文件状态。

每个素材支持：

- 按素材类型使用对应图标进行内置预览或打开；
- 导入默认剪辑软件的素材区，视频、音频、图片和字幕使用同一入口；
- 媒体项目列表提供“导入全部素材”，一次导入该来源下可用的视频、音频、图片和字幕；
- 在资源管理器中定位；
- 将该素材移入系统回收站。

第一版不在每个素材后同时摆放“预览”和“系统打开”两个含义重叠的按钮。

剪辑软件合并在“设置 → 偏好”中统一管理：支持扫描本机常见剪辑软件、切换默认软件，以及手动选择程序。素材条目的导入提示必须跟随当前软件名称变化。不同软件使用独立适配器：剪映使用已验证的文件打开参数；CapCut、Premiere、DaVinci Resolve 和 Filmora 使用各自的导入窗口流程；VEGAS 使用其命令行或脚本入口。无法确认成功时必须返回明确错误，不得只因进程已启动就提示成功。

### 4.4 全部素材视图

“全部素材”是项目视图旁的二级标签页，用于跨项目检索单个素材。

支持：

- 视频、音频、图片、字幕类型筛选；
- 搜索文件名、所属项目和平台；
- 按最近添加、文件名、大小排序；
- 网格和列表切换；
- 打开素材；
- 返回所属项目；
- 在资源管理器中定位。

全部素材视图不得改变项目归属关系，也不得为同一封面生成多条重复记录。

### 4.5 自动入库

- 下载任务只有在文件完整写入并通过完成校验后才能进入素材库。
- 同一来源后续下载的 MP3、封面和字幕必须追加到现有项目。
- 更新素材库时同时更新项目目录下的 `metadata.json`。
- 下载队列中的失败、取消和未完成任务不进入素材库。
- 重试成功后只产生一条最终素材记录，不保留重复失败记录。

### 4.6 扫描与索引重建

第一版必须能够扫描用户当前设置的下载目录：

- 识别平台目录和媒体项目目录；
- 读取项目内 `metadata.json`；
- 验证清单内文件是否存在；
- 将新发现项目加入全局索引；
- 将缺失文件标记为 `missing`；
- 允许清理已经无法恢复的缺失索引；
- 扫描过程在后台执行，不阻塞界面。

对于旧版本生成的时间戳分裂目录：

- 第一版可以识别并标记为“旧目录结构”；
- 可以根据平台和媒体 ID 给出可合并提示；
- 第一版不自动移动或删除旧文件；
- 自动合并和冲突处理放入后续版本。

### 4.7 删除与恢复边界

- 第一版所有删除操作默认移入系统回收站，不直接永久删除。
- 删除前必须明确区分“删除单个素材”和“删除整个项目”。
- 确认框显示将删除的文件数量和预计释放空间。
- 删除单个封面时，应提示项目将失去封面，但不能连带删除视频、音频或字幕。
- 删除项目时，只处理该项目目录内由 VidoGo 管理的文件。
- 删除单个素材成功后立即更新 `metadata.json` 和全局索引；删除整个项目成功后从全局索引移除项目记录。
- 删除失败或部分失败时保留可核对的错误状态，不伪装成成功。

## 5. 页面信息架构

```text
VidoGo Basic
└─ 素材库
   ├─ 项目（默认）
   │  ├─ 搜索
   │  ├─ 平台 / 类型 / 状态筛选
   │  ├─ 排序与视图切换
   │  ├─ 项目卡片或列表
   │  └─ 项目详情面板
   │     ├─ 项目信息
   │     ├─ 视频
   │     ├─ 音频
   │     ├─ 图片
   │     └─ 字幕
   └─ 全部素材
      ├─ 类型筛选
      ├─ 搜索与排序
      └─ 素材卡片或列表
```

## 6. 与现有原型的关系

现有两个 HTML 原型仅作为结构参考，不直接整体嵌入当前应用。

### 6.1 `asset-hub-bundle.html`

作为第一版主要结构参考，保留：

- 项目优先；
- 项目/素材双视图；
- 项目卡片的素材数量汇总；
- 打开项目后按素材类型分组；
- 搜索、筛选、排序和视图切换。

第一版移除或暂缓：

- 一键分发；
- 制作状态；
- 新建作品；
- 复用为模板；
- 国内/国外分发平台分组；
- 独立的完整应用侧栏和品牌栏。

### 6.2 `asset-manager.html`

仅作为“全部素材”视图和单个素材卡片的参考，不作为素材库首页的数据结构。

其中的文案素材、选题和创作项目不进入 VidoGo Basic 素材库第一版；剪辑软件入口仅保留“素材交接”能力，不在 VidoGo 内实现剪辑器。

## 7. 数据模型方向

### 7.1 MediaProject

```text
id                  稳定项目 ID
sourceGroupId       同源聚合 ID
provider            来源平台
mediaId             平台媒体 ID
title               项目标题
sourceUrl           来源页面 URL
folderPath          当前项目目录
coverAssetId        共用封面素材 ID
createdAt           首次入库时间
updatedAt           最近更新时间
status              available / partial / missing
assetCount          素材数量汇总
totalSize           项目总大小
```

### 7.2 MediaAsset

```text
id                  素材 ID
projectId           所属项目 ID
sourceTaskId        原始下载任务 ID
assetType           video / audio / image / subtitle
assetRole           primary / cover / caption / variant
relativePath        相对于项目目录的路径
fileName            文件名
fileSize            文件大小
mimeType            MIME 类型
resolution          视频清晰度
qualityLabel        画质标签
formatId            来源格式 ID
videoCodec          视频编码
audioCodec          音频编码
language            字幕语言
automatic           是否自动字幕
downloadedAt        下载完成时间
status              available / missing
```

### 7.3 项目标识优先级

```text
sourceGroupId
  → provider + mediaId
  → 规范化 sourceUrl 的哈希
  → folderPath（最后回退）
```

项目不能只按标题分组，因为同名媒体可能来自不同来源；也不能只按时间戳目录分组，因为同一来源的不同下载动作可能发生在不同时间。

## 8. 目录与清单规范

第一版继续使用当前已经确定的目录结构：

```text
下载根目录/
└─ 平台/
   └─ 标题 [mediaId]/
      ├─ video/
      ├─ audio/
      ├─ images/
      │  └─ cover.jpg
      ├─ subtitles/
      └─ metadata.json
```

规则：

- `metadata.json` 中的素材路径使用相对路径。
- 全局索引可以保存解析后的绝对路径，但必须能够通过扫描重建。
- 一个项目只能有一个当前封面引用。
- 同一文件路径只能对应一条有效素材记录。
- 同一下载任务重试后不能重复入库。
- 项目目录不存在时标记缺失，不立即从索引静默删除。

## 9. 必须覆盖的状态

### 9.1 加载状态

- 首次加载显示骨架或明确的正在读取状态。
- 后台扫描显示进度，但不遮挡已经可用的项目。

### 9.2 空状态

- 素材库为空时说明：完成一次下载后，视频、MP3、封面和字幕会自动归入同一个项目。
- 提供“前往浏览器”和“扫描下载目录”两个入口。

### 9.3 缺失状态

- 单个文件缺失：项目显示“部分文件缺失”。
- 整个目录缺失：项目显示“项目目录不存在”。
- 提供重新扫描、重新定位目录和清理索引操作。

### 9.4 错误状态

- 清单无法解析；
- 文件无权限访问；
- 项目目录只读；
- 删除到回收站失败；
- 扫描中断。

错误信息必须说明受影响的项目或文件，并提供可执行的恢复动作。

## 10. 第一版不包含的功能

以下功能不进入素材库第一版：

- 手动上传或拖拽导入任意本地素材；
- 自动搬移和合并旧版本的分裂目录；
- 标签系统；
- 收藏和自定义合集；
- 文案、脚本和选题管理；
- 制作中、草稿、已发布等创作状态；
- 视频编辑、字幕编辑或图片编辑；
- 一键分发到社交平台；
- 云端同步和多人协作；
- AI 自动分类、识别或摘要；
- 永久删除和应用内回收站。

这些能力可以在第一版数据模型稳定后逐步增加，不应改变“媒体项目包含多个素材”的基础关系。

## 11. 实现约束

- 素材库必须接入现有 Electron 页面框架，不建立第二套应用外壳。
- 复用现有主题变量、图标系统、内嵌浏览器和预览弹窗。
- 新增可见文案必须进入现有多语言字典。
- 扫描和文件校验在主进程执行，渲染进程不直接遍历磁盘。
- 本地文件访问通过受控 IPC 完成，不向页面开放任意文件系统能力。
- 大型素材库需要分页或增量渲染，封面图片需要懒加载。
- 扫描、刷新和删除操作必须可以安全重入，不能造成重复索引。

## 12. 第一版验收场景

### 场景 A：同源素材聚合

1. 下载某个 YouTube 视频。
2. 素材库出现一个媒体项目。
3. 项目显示视频 1、图片 1。
4. 对同一来源提取 MP3。
5. 仍然只有一个项目，项目变为视频 1、音频 1、图片 1。
6. 再点击下载封面。
7. 项目仍然只有一张封面和一条封面素材记录。

### 场景 B：字幕追加

1. 对已有项目下载中文字幕。
2. 字幕进入同一项目的 `subtitles/` 目录。
3. 项目详情显示字幕 1，并能打开或定位文件。
4. 下载另一种语言字幕后，字幕数量增加但项目数量不变。

### 场景 C：重启持久化

1. 完成视频、MP3、封面和字幕下载。
2. 退出并重新打开 VidoGo Basic。
3. 素材库仍然显示同一项目和正确素材数量。

### 场景 D：扫描已有目录

1. 清空或重建全局索引。
2. 扫描当前下载目录。
3. 素材库根据项目 `metadata.json` 恢复项目和素材记录。

### 场景 E：外部文件变更

1. 在资源管理器中移动或删除某个素材。
2. 刷新素材库。
3. 对应素材显示缺失，项目显示部分缺失。
4. 其他正常素材仍可预览和打开。

### 场景 F：安全删除

1. 在项目详情删除一个 MP3。
2. 确认框明确显示只删除该音频。
3. 文件进入系统回收站，视频和封面保留。
4. 删除整个项目时，确认框显示项目素材数量和预计释放空间。

### 场景 G：界面适配

1. 默认窗口 `1360 × 860` 下项目卡片、筛选和详情面板正常显示。
2. 最小窗口 `980 × 680` 下没有内容遮挡和关键操作丢失。
3. 亮色和暗色主题均可识别项目状态和按钮。
4. 长中文标题、英文标题和多语言字幕名称不会撑破布局。

## 13. 第一版完成定义

满足以下条件时，素材库第一版可以视为完成：

- 用户能从主侧栏进入素材库。
- 下载完成的素材能够自动入库。
- 同一来源的不同素材始终归入一个媒体项目。
- 同一项目封面不会因下载视频、MP3 或封面动作而重复保存。
- 用户能在项目视图和全部素材视图之间切换。
- 用户能搜索、筛选、排序并查看项目详情。
- 视频、音频、图片和字幕均可预览、打开或定位。
- 视频、音频、图片和字幕均可导入用户设置的默认剪辑软件；优先只进入素材区，个别只提供“打开文件”入口的软件，其时间线行为由目标软件决定。
- 可以扫描已有项目并重建索引。
- 外部删除或移动文件后能够显示缺失状态。
- 删除操作进入系统回收站，并正确更新清单和索引。
- 应用重启后素材库关系和状态保持一致。
- 自动化测试覆盖同源聚合、封面去重、索引重建、缺失检测和安全删除。
