# VidoGo Basic 0.2.1 下载页修复验收

## 结论

- 原“素材包完成”横幅不合格：下载页网格只声明两行，新增的第三块内容被压缩并与表格重叠。
- 修复后横幅完整显示，状态、标题、摘要和三个后续动作有独立空间；中文截图见 `03-after-asset-pack-complete-zh.png`。
- 原暂停/继续不合格：yt-dlp 暂停会终止进程，继续时重新解析来源；实测可等待 20 秒以上，证据见 `04-before-worker-resume-20s.png`。
- 修复后 yt-dlp 使用同一工作进程原地暂停/恢复；本地受控下载验收中 `jobId` 不变，恢复首个新进度为 5ms，最终完成。
- 直链下载使用 HTTP Range 续传；验收中恢复首个新进度为 153ms，最终完成。
- 暂停按钮原先会因进度刷新在 pointerdown/pointerup 之间重建 DOM，同时渲染会替换任务对象，造成单击丢失或确认写入旧对象。修复后交互期间延迟重绘并保持任务对象身份稳定；自动测试强制插入进度刷新后，一次点击仍成功暂停。
- 下载器现在由可控监督进程托管；即使 yt-dlp 仍在页面解析、尚未触发进度回调，也能直接挂起/恢复执行子进程。解析阶段暂停/恢复验收保持同一 `jobId`。
- “所有者不限并发”原先被错误实现为无上限启动任务，导致同一素材包的音频和视频解析器争抢资源。现改为套餐不额外限流，但仍遵守本机 1–10 的并发设置。
- yt-dlp 启动阶段现在显示“正在解析”而不是“正在连接”；30 秒内仍未收到首个媒体字节会明确失败并允许重试，不再无限挂起。
- 未完成任务绑定创建任务时的账号；存在未完成任务时阻止切换账号，且其他账号不能继续/重试该任务。已完成的本地文件仍为设备资产，可继续访问。

## 验收边界

受控测试证明了进程内恢复、Range 续传和单击竞态修复。不同网站仍可能受源站限速、签名 URL 过期或服务器不支持 Range 影响；进程已退出或应用重启后的恢复会使用元数据/分片文件兜底，不能承诺与进程内恢复同样的毫秒级延迟。
