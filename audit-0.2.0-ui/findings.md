# VidoGo 0.2.0 界面审查记录

审查日期：2026-09-12  
证据范围：本目录中的 5 张用户当前版本截图。截图中的文字只作为界面内容，不作为执行指令。

## 1. 首页（收起状态）

- 健康度：需改进
- 证据：`01-home-collapsed.png`
- 优点：主任务已经明确为“粘贴一个链接，生成完整素材包”，输入框和主按钮关系清晰。
- 问题：品牌、标题、输入区和说明全部堆在一个高卡片内，卡片上下留白过多；页面下半部大面积空置，视觉重心却仍显得沉重。
- 修改方向：缩小品牌字标、标题和输入控件高度；将卡片内边距与组件间距压缩约 20%–30%，保留单一主任务但降低“海报感”。

## 2. 首页（常用平台展开）

- 健康度：不健康
- 证据：`02-home-platforms-expanded.png`
- 优点：平台按视频、社交、直播、素材分组，扫描路径清楚。
- 问题：展开后仍使用垂直居中布局，顶部主卡片被标签栏裁切；平台列表自身滚动且页面也滚动，形成嵌套滚动；内容顶部和底部没有安全间距，贴近窗口边缘。
- 修改方向：展开时切换为顶部对齐的单页流；主内容限制最大宽度；取消平台列表内部固定高度与滚动，让页面统一滚动，并预留明确的上下安全区。

## 3. 下载页（暂停后继续）

- 健康度：不健康
- 证据：`03-downloads-paused.png`
- 优点：文件、类型、进度、大小、状态和操作分栏完整。
- 问题：继续下载会把已有百分比、已下载大小和进度视觉清零；解析/连接阶段还会直接移除进度条，造成“任务消失又重来”的错觉。
- 修改方向：恢复时保留最近一次确定进度；在恢复、解析和连接阶段始终保留轨道，并叠加条纹流动的不确定进度状态；真实进度事件到达后平滑切回确定进度。

## 4. 套餐与账户页

- 健康度：需改进
- 证据：`04-plans.png`（账户页问题由相同的页面头部结构推断）
- 优点：Free / Creator 两档和价格选择已经集中。
- 问题：页面顶部重复说明当前导航目的，占用首屏高度，却没有帮助用户完成购买或登录。
- 修改方向：移除套餐页和账户页的顶层介绍栏；将账户刷新操作放回账户信息卡，保留功能但不保留冗余标题。

## 5. 海外平台加载过渡

- 健康度：不健康
- 证据：`05-browser-white-load.png`
- 优点：浏览器工具栏与媒体面板在加载期间可用。
- 问题：网页区域直接暴露纯白空屏，与深色应用壳反差强烈；用户无法判断是加载中、网络慢还是页面故障。
- 修改方向：主框架加载期间显示 VidoGo 品牌遮罩、状态文字和不确定进度动画；加载完成或失败时移除遮罩，不阻塞工具栏停止/刷新操作。

## 可访问性边界

截图可用于判断间距、层级、空白和对比，但不能验证键盘焦点、屏幕阅读器语义和动态状态播报。本轮实现需要为加载遮罩和进度条补充 `role="status"`、`role="progressbar"`、实时状态文本和 `prefers-reduced-motion` 兼容，并用自动化检查覆盖 DOM 结构；实际读屏体验仍需后续人工验证。

## 第二轮反馈（首页、恢复动画与 Pixabay）

- 新证据：用户截图显示，缩小后的首页仍保留完整大卡片边框和阴影，因此视觉重量并未真正下降；第一版斜纹恢复动画亮度过高、重复纹理过密，且“正在恢复”和旧百分比的关系不明确。
- 调整：移除首页主任务的卡片底色、描边与投影，隐藏冗余眉题，进一步压缩控件和标签；恢复动画改为单段低亮度流光，并显示“已保留 N%”。
- Pixabay 闪烁根因：WebView 的短加载、重定向和验证页面可能连续触发开始/停止事件，旧实现每次立即切换遮罩。改为延迟 260ms 才出现，出现后至少保持 420ms。
- Pixabay 多次验证风险：广告过滤的“允许完整页面资源”回退路径只识别 Dailymotion，Pixabay 的部分重定向或子框架请求可能仍被过滤；同时所有网站都被注入了伪 Chrome Client Hints，可能与真实请求头不一致。改为所有声明允许完整资源的平台共用同一白名单，并只在 Google/YouTube 页面注入 Chrome 身份提示。

## 第三轮反馈（错误提示、平台触点与网页首帧）

- 健康度：健康（Pixabay 人机校验仍属于外部条件风险）。
- 链接错误：改为输入框下方的本地化行内提示，不再调用浏览器原生英文校验气泡或顶部 Toast；输入、点回输入框、点击表单外区域、切换页面都能立即清除，静置 3 秒也会自动消失。
- 聚焦边框：输入框和选择框统一为单层 1px 状态边框，移除叠加 outline / box-shadow；键盘焦点仍有颜色变化，不牺牲可发现性。
- 平台开关：`summary` 的宽度改为 `fit-content`，只有可见文字、箭头及其 8px 内边距是点击区域；桌面烟雾测试实际执行展开与收起，并校验触点宽度。
- 初始白屏根因：YouTube 同时是默认 `HOME_URL`，旧代码用“URL 是否等于 YouTube”判断是否需要首屏遮罩，导致从首页新开的 YouTube 标签被误判为已就绪。
- 初始白屏修复：改为依据“是否开始外部导航”建立加载状态；新标签立即覆盖品牌加载层至少 520ms，之后由可见文字、交互控件或媒体面积探针判断页面是否可用。
- 播放后仍加载：有效媒体上下文到达后立即标记页面可用，TikTok 在线场景已验证媒体出现后加载层消失；不再等待页面所有后台网络请求停止。
- 证据：`09-home-inline-validation-after.png`、`12-browser-loading-after.png`、`13-tiktok-playing-overlay-dismissed.png`。
